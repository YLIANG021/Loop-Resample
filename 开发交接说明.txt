--------------------------------------------------------------------------------
1. 项目概述
--------------------------------------------------------------------------------
1.1 这是什么
    一个 Blender 5.2 编辑模式插件（extension，模块路径
    bl_ext.user_default.loop_resample）。功能：选中一条或多条边路径（loop/path），
    进入"调整模式"后加减段数（resample），同时把路径两侧受影响的面带（strip）
    拆除重建，并尽可能完整地保留：边属性（seam/sharp/crease/bevel 等浮点层）、
    面属性（material_index、smooth）、UV（多 layer、多 island、跨 0/1 环绕）。

1.2 目录结构
    __init__.py          插件注册/注销入口；注销时 sessions.clear()
    operators.py         四个算子：begin / step / confirm / cancel；_resample 主流程
                         （begin/step 是面板两击时代的遗留，现已无人调用，见 8.30）
    ui/                  【目录结构已变，1.2 这一段长期落后于代码，改动前先以实际文件为准】
      interactive.py     滚轮 modal 算子 + 菜单转发算子 + _viewport_area
      hud.py             overlay 绘制：3D 数字、chip 行、描边与圆点（含抬升两常量）
      panels.py          编辑模式右键菜单项的 draw 函数（面板类已删）
    core/session.py      会话容器：锁定源网格、编辑模式守卫（timer）
    core/paths.py        选中边→有序路径、闭环相位同步
    core/regions.py      路径→受影响区域（STRIP/CAPPED_STRIP/FAN/NGON_CAP）；
                         冻结测量帧 region_frames / region_rails
    core/curves.py       冻结的 C0 重采样曲线（按段数采样出坐标）
    core/planner.py      条带重建计划（quad/tri 排布、rung 连续性打分）
    core/rebuild.py      BMesh 拆除与重建（detached path、triangle fan、ngon cap、
                         ordered strip）
    core/attributes.py   边属性 + 点级属性（顶点组权重、点域顶点色）的捕获/重采样/应用；
                         归一化参数与投影工具
    core/surface.py      面属性 + UV + corner 域顶点色的捕获与应用（按岛分链，本插件最核心也最脆弱）
    core/geometry.py     法线参考等几何工具
    core/utils.py        _point 等小工具
    core/diagnostics.py  print_timing 等诊断输出
    core/types.py        轻量数据类型

1.3 运行环境要点
    Blender 二进制：C:\Program Files\Blender Foundation\Blender 5.2\blender.exe
    headless 跑法：blender.exe -b --python <脚本>（千万不要加 --factory-startup，
    否则插件不加载）。-b 模式下 bpy.app.timers 不 tick，timer 行为要直接调回调。
    无关插件噪声：uvpackmaster4 的 GPU SystemError、hot_node 卸载时
    FileNotFoundError，忽略即可。

--------------------------------------------------------------------------------
2. 核心概念与坐标框架（理解一切的钥匙）
--------------------------------------------------------------------------------
2.1 path（路径）
    用户选中的边构成的有序链，(vertices, edges, is_closed)。多条 path 时闭环
    相位会同步（synchronize_closed_path_phases，提交 6eb9595），保证相邻区域
    对同一条共享轨的顶点顺序一致。
    闭环起点（path[0][0]，下称 anchor）是重建中唯一保留元素身份、且采样相位
    零点对齐的顶点：rebuild_detached_path 把 samples[0] 写回它，其余顶点全部
    新建。anchor 的选择规则见 8.9（seam 优先，否则 index 最小）。

2.2 region（区域）
    每条 path 两侧受重建影响的面集合。种类：
    - STRIP：两侧都是四边形梯带；
    - CAPPED_STRIP：梯带尽头是 n-gon 盖或三角扇；
    - FAN：一侧收敛到一个极点（pole），重建为绕极点的三角扇；
    - NGON_CAP：整个闭环边界围成一个 n-gon。
    region 字典关键字段：faces、delete_edges、path_index、outer_path_index 或
    outer_vertices、material_index/smooth（区域默认值，仅作兜底）、frames、
    edge_attributes、source_faces、phase_locked。

2.3 rail（轨）与 (u, v) 面坐标
    每个区域有两条轨：内轨 = 选中的 path（v=0），外轨 = 另一侧边界（v=1）。
    u = 顶点沿轨的归一化位置 ∈ [0,1]：源顶点 i 位于 u = i / segments，
    segments = count - (0 if closed else 1)。
    因为 v 只取 0/1 两个值，"quad 双线性 / triangle 重心"这类二维插值全部退化为
    "沿所属轨做一维插值"——这是 surface.py 的根本简化，不要试图引入二维插值。

2.4 归一化参数为什么重要
    所有捕获量（边属性位置、面跨度、UV 节点）都存放在"进入那一刻的源折线"
    这个冻结框架里。后续任何段数下，当前顶点都通过投影（path_projection /
    normalized_parameters）回到这个框架取值。这样捕获与应用的段数可以不同，
    且 N→M→N 能逐位复原。

2.5 冻结测量帧 region["frames"]
    {"closed", "inner": {"points","segments"}, "outer": {...}}。
    为什么必须冻结：rebuild_detached_path 会就地移动轨的首/尾顶点坐标，活网格
    在重建后不再是合法测量基准。边属性捕获、面/UV 捕获、region_outer_parameters
    三者共用这一个帧定义（core/regions.py），不要各自再算一份。

--------------------------------------------------------------------------------
3. 会话模型（core/session.py）
--------------------------------------------------------------------------------
3.1 生命周期
    begin(context)：读编辑网格→selected_paths→相位同步→ResampleSession(obj,
    live_bm.copy(), paths)→释放旧会话→注册 _watch timer→返回 session。
    step：operators 里 session.next_counts / samples 驱动。
    confirm：提交当前编辑网格，end(context) 释放会话。
    cancel：还在 EDIT 模式内，走自己的恢复路径（把进入前的网格写回），再释放。
    退出编辑模式：timer 触发 discard()（见 3.3）。

3.2 为什么每一步都从源副本重推
    session.source 是进入时的 detached BMesh 拷贝。每一步：
    working_bm = session.source.copy() → 在其上推 paths/regions → 捕获属性 →
    采样冻结曲线 → 拆除重建 → 应用属性 → staging mesh 往返提交到编辑网格。
    没有任何状态从"上一步的网格"继承。收益：区域身份、外轨顺序、相位、复原性
    全部由构造保证；代价：每步 O(网格) 重建，可接受。

3.3 编辑模式守卫
    _watch：0.1s 间隔的 bpy.app.timers 轮询（persistent=True，跨文件加载存活；
    对象被删时 _editing 的 ReferenceError 分支自清理）。发现非 EDIT 就 discard()：
    session.open_bmesh() 拿源副本→to_mesh(obj.data)→update→释放。返回 None 自停。
    discard 用 _release()（只释放会话）而不是 clear()（会注销 timer），因为
    discard 正运行在该 timer 内部。
    注意（对用户说明过）：这个恢复在 Blender undo 系统之外，退出编辑模式后
    Ctrl+Z 不会把它回退。

--------------------------------------------------------------------------------
4. 每一步的数据流（operators._resample）
--------------------------------------------------------------------------------
    1) working_bm = session.source.copy()
    2) paths = session.paths(working_bm)（在 pristine 副本上重推）
    3) regions = capture_adjacent_strips(working_bm, paths)
    4) path_states = capture_path_edge_attributes(paths, working_bm)
    5) 每个 region：region["frames"] = region_frames(region, paths)
       region["phase_locked"] = 两端 path 是否都在同步集合里
    6) 每个 region：region["edge_attributes"] = capture_region_edge_attributes(...)
    7) 每个 region：region["source_faces"] = capture_region_faces(working_bm, region, paths)
       （顺序不可换：frames 必须先于一切捕获；捕获必须先于任何重建变更）
    8) snapshots = session.samples(counts, path_anchors)
      （**必须排在捕获之后**：path_anchors 由 core/seams.py 的 region_seam_crossings
       从缝横穿的两条轨点反推（8.26 起取代已删除的 rail_seam_anchors），采样不再是第一步）
    9) 拆除：detach_adjacent_strips + cleanup_detached_edges
    10) 重建：按 region 种类 dispatch（rebuild_detached_path / rebuild_ordered_strip /
        rebuild_triangle_fan / rebuild_ngon_cap）
    11) 应用：apply_region_faces(...) 然后 apply_region_edge_attributes(...)
        路径边：apply_path_edge_attributes(...)
    12) staging mesh 往返提交 + 重绘
    失败安全：任何异常被算子捕获，报告 "Loop Resample failed safely: <exc>"，
    编辑网格保持上一步状态。

--------------------------------------------------------------------------------
5. 边属性 / 点级属性（权重与点域顶点色）管线（core/attributes.py）函数级说明
--------------------------------------------------------------------------------
5.1 _edge_state / _apply_edge_state
    边状态字典 {"seam","sharp",<浮点层名>:值}。注意 BMesh 的 edge.smooth 是
    Mesh.use_edge_sharp 的反义。浮点层绝对值 <= 1e-6 视为不存在。

5.2 capture_path_edge_attributes(paths, bm)
    按路径边顺序冻结状态列表，供 apply_path_edge_attributes 按区间重采样。

5.3 path_projection(points, is_closed, target)
    点到折线的最近段投影，返回 (段内参数(0..segments), 段切线)。

5.4 normalized_parameters(points, is_closed, vertices, segments)
    把任意顶点列表放回冻结框架，得 u 列表。外轨重建后顶点数变了也靠它归位。

5.5 capture_region_edge_attributes(regions, paths, bm)
    只记录"会被重建销毁"的边（_destroyed_region_edges：所有邻面都在区域删除集里）。
    每条记录 {u, outer_u, state}：
    - 边的一端在路径上：u = 该路径顶点索引（锚定共享顶点，使跨路径的缝连续）；
    - 否则投影中点得 u；与路径平行（|dir·tangent| > 0.5）的边跳过（无对应横档）；
    - outer_u：另一端点（或无锚点时为 None）投影到外轨冻结帧。
    路径自身的边不在此记录（由 5.8 恢复）。

5.6 merge_edge_states(weighted) / resample_edge_states(parameters, states, closed)
    源边 i（共 M 条）拥有区间 [i/M,(i+1)/M]（开闭路径同式，开路径末顶点在 u=1）。
    新边取其覆盖的所有源区间的加权合并：离散标志加权多数、平局偏向"保留"
    （丢缝比多缝危害大）；浮点层加权平均，缺失按 0 计权。
    性质：减段数是 blend 不是丢弃；加回原段数落回原值。

5.7 apply_region_edge_attributes(rebuilt_faces, region, inner_vertices,
    inner_parameters, outer_vertices, outer_parameters, bm)
    在重建结果里收集横档（恰好一端在内轨上的边），按 (u 代价, outer_u 代价, inner_index,
    横档序号) 四级排序做最近匹配；同一横档可能合并多条记录（减段数时）。
    外轨代价用于区分共享内顶点的两条横档（梯带加三角时会出现）；第三级 inner_index 是
    跨区域的确定性来源——共享同一路径的两个区域各自遍历自己的面，横档序号不可比，而
    inner_index 两边算出来一样，所以红线不会在路径上折（详见 8.26）。
    【8.26 起】seam 记录另有一条窄化通道：先用 `_outer_anchor_index` 认出这条缝当初出发
    的那个**存活外轨顶点**（定轨时该值与捕获值逐位相同，故容差取 1e-7），再把候选池收窄到
    挂着那个顶点的横档 `rungs_by_outer`。这样红线一定接得上未修改区，而不是停在差一列处。
    锚点找不到 / 外轨本身是被重采样的路径 / FAN、NGON_CAP 无外轨——都退回全池位置匹配。

5.8 apply_path_edge_attributes(updated_paths, path_parameters, source_states, bm)
    路径自身边用 resample_edge_states 的结果逐边写回。

5.9 region_outer_parameters(region, outer_vertices)
    读 region["frames"]["outer"]，把重建后的外轨顶点投影回冻结帧。

5.10 点级属性：顶点组权重 + 点域顶点色
    （capture_path_point_attributes / apply_path_point_attributes）
    点级、随 path（内轨）顶点重采样，比边属性简单（纯连续插值，无区间合并、无离散
    投票）。_point_value_layers 列出本管线携带的所有"顶点级"层，元素为
    (kind, name, layer)：kind=="weight" 取 bm.verts.layers.deform.active，
    kind∈{"color","float_color"} 取 bm.verts.layers.color / .float_color 里已有的层。
    一律"只读已存在的层"：deform 用 .active 而非 verify()，颜色只遍历集合而不新建，
    所以既无顶点组又无点域色的网格返回 None、全程 no-op，绝不凭空建层
    （守住不变量 d 区域外不受影响）。
    为什么点域色走这里而不走 6.9 的链：它是每个顶点一个值，不存在"同一 u 上角值
    分歧"的缝语义，按 u 沿 path 插值就是它的正确解；且它写在 vertex 上，一次赋值
    影响该顶点所有面，用角链反复写反而多余。
    位置计算 _point_positions：源顶点 i 位于归一化 u=i/segments（闭合 segments=count、
    开放=count-1），新顶点按其 u 落在相邻两源顶点之间，返回 (left, right, factor)。
    混合分两种：_blend_weights 对 dict 权重，落在源顶点上（factor 0/1）原样拷贝该
    顶点权重（连 1e-7 这种极小值都保留）→ N→M→N 逐位复原，只有真正混合处才用
    DEFORM_WEIGHT_TOLERANCE=1e-6 去噪；_blend_values 对 4 分量 Vector 用 lerp，同样
    在 factor 0/1 直接 copy 端点。闭环环绕用 %source_count。
    只重写 path 顶点：外轨若固定则顶点与其值本就未动，若外轨自身是 path 也已作为另一
    条 path 在此处理。扇心极点非 path 顶点，值随元素保留。
    接入点：operators._resample 捕获段（path_states 之后）与应用段
    （apply_path_edge_attributes 之后）各加一行。

--------------------------------------------------------------------------------
6. 面/UV/corner 顶点色管线（core/surface.py）函数级说明 —— 最核心
--------------------------------------------------------------------------------
6.1 历史根因（为什么旧实现必须删）
    旧 capture_region_face_attributes：整区域 Counter 多数投票选 material/smooth
    → 丢失逐面对应。
    旧 capture_region_uv_attributes：_vertex_uv_samples 把一个顶点在区域所有面上
    的所有 loop 的 UV 平均成一个值，再写回该顶点每个 loop → 跨 UV 岛的顶点被
    抹平（用户最初"跨岛就烂"的根因）。这两个函数已删除。

6.2 捕获 capture_region_faces(bm, region, paths)
    对每个源面（跳过无内轨角的面——深度>1 区域的外排没有对应重建面）：
    - 每个 loop 角记 {vertex, rail, u, uv:{层名: Vector}}；不在任何轨上的顶点
      （扇心极点）rail=1、u=None，稍后替换为该面内轨角的弧心 _u_center；
    - 面的 u 跨度 [u_start,u_end] 与 u_center 由其内轨角的最小覆盖弧 _u_span 得出
      （闭环上取"最大间隙的补弧"）；
    - 角进入两条轨的并查集 _RailBuilder（见 6.3）；
    - 记录 {material_index, smooth, u_start, u_end, u_center, chains}，chains 为
      {rail: token}，最后统一翻译成链下标（见 6.5）。
    返回值 {"closed", "records", "rails": [链列表, 链列表], "periodic"}。

6.3 _RailBuilder（并查集建链）
    节点 key = (u, 各层 UV 舍入到 6 位小数的元组)。同一 u 上 UV 值不同 → 两个节点
    → 这就是 UV 缝，不需要显式缝检测。
    边 = 源面沿该轨的面边（face.edges 中两端都在该轨角集合里的边）：把两个节点
    缝合进同一连通块。
    连通块 = 链 = 一个岛沿该轨的连续折线。
    wrap edge：closed 区域里 |u_a - u_b| > 0.5 的面边（跨 0/1）。检测必须放在
    "同连通块则跳过"之前——闭环上跨 0/1 的面最后到达，那时两端点已被前面的面
    缝合，先跳过就永远记不到 wrap（历史 bug，见 8.5）。含 wrap edge 的链
    closed=True。
    链输出 {"closed", "knots": [(u, {层: Vector}) 按 u 升序]}。

6.4 应用 apply_region_faces(bm, rebuilt_faces, region, inner_vertices,
    inner_parameters, outer_vertices, outer_parameters)
    - 新面每个角定 (rail, u)：内轨顶点用 inner_parameters；外轨顶点用
      outer_parameters；都不在（新扇心）→ rail=1, u=None；
    - 面中心 = 内轨角 u 的最小覆盖弧心；_match_face 按"新面 u 区间与源面 span 的
      重叠取多数"选源面（重叠为 0 才退回最近中心），继承其 material_index / smooth；
      改重叠多数的原因与边界见 8.12；
    - 每个角在 record["chains"][rail] 这条链上 _sample_chain 取样写回 loop。
      共享新顶点的两个新面匹配到相邻源面 → 同链 → 同一段 → 同一个值：岛内连续；
      缝两侧是不同链：跨岛分开。这就是"单岛连续 + 跨岛不混"的同时成立。
      注意：不要试图在角点上"按 u 覆盖情况改选别的链"——已被用户实测打回（历史见 archive 里的 8.13）。

6.5 token 而不是根（历史 bug，见 8.4）
    add() 返回的是节点 key（token），不是并查集根：后续面的合并会换根，若记录
    存根，翻译链号时 KeyError（用户现象："点一下就报
    Loop Resample failed safely: (0.1875, (('UVMap', ...),))"）。
    翻译在所有面捕获完后统一做：indices[rail][builders[rail]._find(token)]。

6.6 _sample_chain(chain, u, periodic)
    单点链直接返回该点值（扇心极点每面一条单点链 → 共享极点也保岛）。
    closed 链：末尾追加 (首 u + 1, 首值)；u < 首 u 时 u += 1（跨 0/1 连续）。
    开链：两端夹取。
    段内线性插值；factor 夹 [0,1]；factor>=1 返回 second.copy()、factor=0 经
    lerp 精确返回 first —— 这是 N→M→N 逐位复原的关键，不要"优化"掉。

6.7 周期层 _periodic_layers / _lerp_uv / _lerp_wrapped
    仅当区域闭合且该层捕获范围落在单 tile [-1e-4, 1+1e-4] 内，才认为周期=1 并做
    ±1 展开（跨缝面存 0.99/0.01 时普通 lerp 会扫回 0.5）。跨多 tile 的是图集
    偏移，周期未知，猜了会整 tile 平移（历史 bug，见 8.3）。

6.8 特殊几何
    - FAN 极点：rail=1 单点链；u=None 的角用面中心取样（单点链与 u 无关）。
    - NGON_CAP：全部角在 rail=1，面边含跨 0/1 边 → 整环一条 closed 链。
    - 深度>1 区域的外排面：捕获时跳过（重建把多排塌缩成一排梯带，只有内排有
      对应面）。

6.9 corner 顶点色与 UV 共用链（capture_region_faces / apply_region_faces 扩展）
    【Blender 5.2 的 BMesh 颜色 API 事实，实测于 5.2.1 LTS】颜色按"字节/浮点 ×
    点域/角域"分裂成四个集合，元素一律是 4 分量 mathutils.Vector，直接
    loop[layer] / vertex[layer] 读写，没有 4.x 的 .color 包装，也不再需要
    mathutils.Color：
      BYTE_COLOR/CORNER  → bm.loops.layers.color
      FLOAT_COLOR/CORNER → bm.loops.layers.float_color
      BYTE_COLOR/POINT   → bm.verts.layers.color
      FLOAT_COLOR/POINT  → bm.verts.layers.float_color
    BMCustomLayer 上也没有 data_type 可读（返回 None），"是哪一类"只能靠遍历哪个
    集合得知，所以 kind 由遍历方给定。
    _corner_layers(bm) 把 uv + 两类 corner 颜色统一成 {(kind, 层名): (kind, layer)}，
    捕获与应用共用它，避免两边键序写歪。corner 值全部按 Vector 原样存（含 alpha）。
    颜色进入 _RailBuilder._key（对所有分量逐位舍入），所以"同 u 同 UV 但颜色不同"
    的角也会分裂成两条链——颜色跳变被当作缝一样保留、不被平均。这是有意的取舍：
    宁可让颜色硬边界像 UV 缝一样切链，也不丢色。
    _lerp_value 按层分发：仅"闭合区域且落在单 tile 内"的 UV 层是 periodic，走
    _lerp_uv 的 ±1 展开；颜色层与多 tile/开链 UV 一律走通用 Vector.lerp（factor 0
    精确返回 first，保住逐位复原）。bounds/periodic 只对 UV 计算。
    点域颜色不在这里处理，见 5.10。
    无颜色层时 value_layers 只剩 uv、_key 分量数=2、分发全落到旧的 Vector.lerp 分支
    → 逐位行为与扩展前完全一致（零回归）。operators 不需要为此改动（都在这两个函数
    内部完成）。


6.11 采样器的 anchor 语义（curves.py，8.26）
    sample_catmull_rom_curve(curve, count, anchors=())：
    anchors 非空**且**（count ≠ 源控制点数 或 源 profile 无效走均匀回退）时，改走
    _pinned_samples——按锚点把曲线切成若干弧段，用 _allocate_interval_segments 按
    弧长比例给每段分配段数（每段至少 1 段），锚点处精确取 control_points[i]，段内在
    弧长上均匀取样。段数放不下全部锚点时 _pinned_samples 返回 None → 退回今天的
    普通分布（**静默降级**，不报错、不失败）。
    为什么 count == 源段数时不钉：那条路径本来就是逐控制点恒等采样（每个源顶点都
    被踩中），钉了反而破坏 N→M→N 逐位复原（不变量 a）。
    sample_by_arclength(..., forced_anchors=())：把锚点并进 detect_feature_anchors
    的结果再排序；随后 _limit_feature_anchors 在段数吃紧时仍可能按转角强度把锚点丢掉
    ——同样是静默降级，因为这条只在 curve is None（拟合失败）时才走。
    诊断：控制台每步打印 [Loop Resample][diagnostic] seam-crossings path0:[3,12]->15 …
    方括号里是该 path 被钉住的源顶点序号，箭头后是目标段数。若方括号比目标段数还长，
    就是降级了（该步仍可能塌陷）。

8.26 【2026-09-21，已实现，尚未提交】缝不再约束几何：删掉 planner 的整套缝机器，改为建好后按"接得上未修改区"事后赋予

    来源：用户把需求重新表述了一遍——"我其实并不想用那些属性来约束我的点线面，只是让它来
    约束点线面生成后，缝合边属性的赋予"；具体要求是"修改区里面的红边，一定有一段是连着
    修改区与未修改区的交点的，另一端理想情况下也能连上；两端连上、中间连不上我也能接受"。
    这直接推翻了 8.19→8.24 五轮迭代的**前提**：那五轮全都在让缝去约束阶梯怎么走。

    现象（8.19~8.24 一直没修好的那个）：一条缝横穿条带时，红线在受影响带里断开或停在
    离未修改区差一列的地方。8.21/8.22 把它归因于"阶梯偏移 d 只能单向变化"，8.24 归因于
    "1e4 罚分把三角赶离缝列"，两次都在改 DP 的代价函数。

    根因（这一轮才看对的）：`apply_region_edge_attributes` 里**根本没有连通性概念**。它对
    每条源记录独立做 `min(every_rung, key=rung_cost(...))`，`outer_u` 只当二级 tie-break。
    于是一条缝的远端可以落到"离未修改区边界顶点差一列"的横档上——红线就停在那儿。
    而 planner 那边无论怎么罚分、怎么切段，都改变不了这个匹配规则；反过来，为了让缝落在
    特定格点上而付出的代价（8.22 的面数上涨、8.24 的三角簇）全是白交的。

    关键事实（决定了新做法为什么可行，都已在代码里核对过）：
      - 阶梯图是**连通**的，而且每个外轨顶点上至少挂着一根横档（`_transition_face` +
        `_advance`：QUAD 在节点 (i,j) 和 (i+1,j+1) 各出一根横档，INNER_TRI 在 (i,j) 出两根，
        闭环还有取模回绕那一根）。所以"两端连上"这件事**不需要几何让路**，恒成立。
      - 面数 = max(inner_steps, outer_steps) + extra，而 extra 是"为了保缝多花的面"
        （8.22 引入）。删掉缝机器后 extra **恒为 0**，面数回到最小值。
      - 不存在"先三角化再合并成四边形"这一步，所以"保护某些边不被四边形化"这个需求
        （用户提过）解决的是一个不存在的问题——每根横档都是真边，缝永远不需要四边形对角线。
      - 定轨（outer_path_index is None）时，捕获记的 `outer_u` 与重建后
        `region_outer_parameters` 算出的 `outer_parameters[k]` 是**同一个点在同一条冻结折线
        上的同一次投影**，逐位相同。所以用一个极小容差就能判"这条缝当初是从哪个存活的外轨
        顶点出发的"，不需要模糊匹配。

    做法（一个提交，不拆）：
      新增 —— `core/attributes.py`（+~50 行）
        * `OUTER_ANCHOR_TOLERANCE = 1e-7`：只用来把"逐位相同"与"真的是另一个顶点"分开；
          相邻外轨顶点在归一化参数上至少差 1/count，所以这个值宽得离谱也安全。
        * `_outer_anchor_index(outer_u, outer_parameters, closed)`：返回这条记录的远端当初
          所在的那个**存活外轨顶点**下标，找不到就返回 None。
        * `apply_region_edge_attributes` 里：先按外轨顶点把横档建索引 `rungs_by_outer`
          （把缝的查找从"记录 × 横档"的乘积里摘出来），然后**只有 seam 记录、且外轨是定轨**
          时才把候选池收窄到 `rungs_by_outer[anchor]`；其余一切记录仍走全池。
          池为空/锚点找不到/外轨本身是被重采样的路径（outer_path_index 非 None，两端都是
          新点）/FAN、NGON_CAP（压根没有外轨）——全部退回今天的位置匹配，不会 KeyError。
        * `rung_cost` 的排序键从 `(primary, secondary)` 改成
          `(primary, secondary, inner_index, index)`。**必须**以 `inner_index` 收尾：
          共享同一条路径的两个区域各自遍历自己的面来枚举横档，`index` 在两边不可比，
          而 `inner_index` 是 `updated_paths[path_index][0]` 的下标、两边算出来一模一样。
          这是"红线不在路径上折"的唯一保证（8.22 靠 pinned 集合保证，那套已删）。
      删除 —— `core/planner.py`（−354 行里绝大部分）+ `core/diagnostics.py`（−40 行）
        * `SEAM_ALIGNMENT_PENALTY = 1.0e4` 常量；
        * `_rail_frame_point`、`_seam_rung_nodes`、`_seam_alignment_cost`（8.19）；
        * `_seam_offset_band`、`_drop_unreachable_seam_nodes`、`_reachable_step`、
          `_seam_waypoint_chain`、`_build_segmented_transitions`（8.21/8.22）；
        * `_build_transitions` 的 `seam_nodes/start_inner/start_outer/end_inner/end_outer`
          五个形参、`_local_transition_pair_score` 的 `seam_nodes`、
          `_beautify_transitions` 的 `seam_nodes/swap_boundaries` 与 `segment_frames` 回放表；
        * `build_ordered_strip_plan` 里 seam_found/seam_band/seam_nodes/seam_dropped/
          seam_waypoints/solve_seam_nodes/pinned_columns 整块，以及包着
          `_build_segmented_transitions` 的 try/except ValueError 降级；
        * `diagnostics._seam_node_list` 与 `print_seam_rungs`。
        * **保留** `diagnostics.print_seam_anchors`——那是 UV 锚点，走的是另一条通道。
      顺手 —— `_beautify_transitions` 里原来 `segment_frames.get(index)` 恒为 None（未切段时），
        现在改成函数开头算一次整带 `distribution_frame` 传下去。`_triangle_distribution_cost`
        的 `frame is None` 分支算的就是同一个整带 frame，所以这一改**逐位等价**，只是省掉
        每次调用重算。`align_outer_boundary` 的 docstring 里"one nearest seam"改成
        "one rotation"——planner 现在已经不认识 seam 了，那句话会误导。

    为什么是一个提交、不按文件边界拆两个：加了不删 → 旧的钉点还在，会把新选择盖住，测不出
    东西；删了不加 → 比今天更差（缝完全随机落）。两者都不是"能独立验收的一步"。

      −0.0 扰动排序；`_build_segmented_transitions` 在 waypoints=() 时 ends 只有一项

做法（一句话）：**裁的是"链"，不是"带子"**。`begin()` 先静默跑一遍捕获，问 pair 阶段

`curves.py` 的 `forced_anchors` 钉住切点）要改 5 个文件、并且每处索引都得换算，

    a) 闭合链不裁（环上没有"端点"可裁）；

9. 不变量与手动回归清单
--------------------------------------------------------------------------------
9.1 不变量
    a) N→M→N 逐位复原（顶点/边/面/每角 UV/每角顶点色/点域顶点色/顶点组权重/材质/
       smooth/seam/sharp/浮点层）。【8.27 起】"每角 UV"这一项**只在 UV 开关打开时**成立；
       关掉时重建带的角 UV 是 bmesh 默认值，不属于"复原"范畴（见 8.27 取舍 a）。其余各项
       两个状态下都必须成立。
    b) 岛内连续：共享顶点的相邻新面 UV 相同；缝边数与源网格相同。
    c) 跨岛不混：一个面的所有角始终在同一岛内。
    d) 区域外网格完全不受影响。
    e) 退出编辑模式 / 取消 = 进入前状态逐位一致。
    f) 确认/取消/退出后无 session、无 timer、无 staging mesh 残留。
9.2 手动清单（用户的工作流，插件内不放测试套件）
    单岛环带加减→回原段数比对；跨缝环带加减；环绕型 UV（0/1 相接）加减；
    扇形盖（极点）加减；n-gon 盖；开放网格行；多材质多 smooth 混合区域；
    退出编辑模式看是否还原；UV 编辑器目视岛是否连续/分离。
    【8.12 相关】多材质/多 smooth 混合区域加减→边界两侧面的材质与 shading 是否
    跟着"新面主要覆盖哪侧"走、不再因中心点越界整面跳变；N→M→N 仍逐位复原。
    【8.26 相关】本轮是**行为改动**，不是性能改动，所以验收看形状不看数字。
    三个用例，从最关键的开始：
      1) 一条缝横穿条带、缝的两端都落在**未修改区**（开放单行条带最直观）：加减段数后
         那条红线应当**两端都接上**未修改区的红线，中间允许折、允许走斜线，但不允许断头
         停在离边界差一列的地方。这是本轮唯一的硬指标。
      2) 一条路径一次穿过**多根**缝（用户那个 3 缝曲面就是标准用例）：同一条路径两侧的
         两个区域，红线在**路径上**必须接得住、不出现错位台阶。判据是目视——旧的
         "两行 pinned 内层下标集合必须相同"那把尺子已经随 8.19-8.24 的机器一起删了。
         若看到红线在路径处错开一列，那是 `rung_cost` 第三级 inner_index 没能对齐，
         属于要查的问题。
      3) 无 seam 的网格：走位、面数、UV、颜色、权重必须与 6787efc **逐位一致**。
         这是本轮唯一保留的旧判据，也是"删机器没删坏几何"的兜底。
    另外必须看的：
      - **面数应当下降或持平**，且回到源段数那一次必须等于 max(内,外)（旧的 extra 恒为 0）。
        面数上涨就是回退信号；
      - 三角摆位：8.24 那个"缝列一根三角都不挂"的簇应当消失，三角沿带均匀散开。
        现在没有任何代价项为缝让路，摆位只由 step-cost + 三角散布 + 横档连续性决定；
      - 控制台：`seam-rungs` 一行照旧出现（字段已缩减为 region= / path= / rungs=N

        汇报沿路径走的红线段；
        `scan-rung-match` 的 work 明显下降（口径改成了实算比较次数，见 8.26）；
      - FAN（扇形盖）与 NGON_CAP 区域：这两类没有外轨，缝走全池位置匹配，行为应与
        改动前一致。若这两类区域上报错或缝乱跳，回来报告；
      - 外轨本身也是一条被重采样的路径（两条平行路径之间）：两端都是新点，缝同样走
        全池匹配，**不保证**接得上——这是设计上的取舍，不算 bug；
      - N→M→N 回到源段数仍逐位复原。

    FLOAT/POINT，顶点绘制默认给的是 FLOAT 那一档）：环带加减→颜色随段数平滑、跨岛不混、
